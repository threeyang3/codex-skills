# MediaBase 仓库维护

- 优先接续已有迁移、UID 对照、代码分支和回执。先确认操作的是正式 MediaBase、只读来源 MediaArchive、隔离副本还是代码仓库，尤其留意 Obsidian 切换菜单里的同名旧库和测试库。
- 看到一处页面异常时，追查同类记录。按「原始来源 → 整部作品或版次身份 → 库内字段与关系 → 插件实际渲染」定位问题。检查真实同类样本后再批量处理，按证据充分程度分别交付。
- Series、Work、Note 各有独立 Markdown 与 UID。属性与链接决定关系，目录用于收纳。主题或创作者补链默认追加关系，保留作品已有系列。只有明确属于某处物理归档且任务要求归档时才移动 Work 与有关 Note。
- 区分作品资料、平台数据、用户数据。Series 手填总评与已评分成员均值独立。明确的零值、未记录、已完成无进度有不同含义。
- 按任务读取 [归档和来源规则](references/library.md) 或 [环境、验证与写入](references/verification.md)。涉及批量移动、来源补写、插件构建或正式部署时读后者。涉及页面、浮层或 Components 时同时查 [界面验收](references/ui.md)。
- 汇报实际修改、覆盖范围、待核对项和验证层级。个人资料、附件、备份、原始审计均留本机。远端提交、推送和合并沿用当前请求的授权范围。发布前把实际验收的构建与提交核对，确认是原私有仓库及预期目标分支。
