# 环境、验证与写入

## 定位

- 先从用户指定位置或 Obsidian 的库登记定位正式 `MediaBase` 与只读来源 `MediaArchive`。在 macOS 上可用 `~/Library/Application Support/obsidian/obsidian.json` 的库登记、根目录结构和最近写入回执复核。Obsidian 中移除一项库登记与删除磁盘目录是两件事。
- 从用户提供的工作区定位 Media Core，并用 Git 核实插件仓库根目录。`文娱实验室/` 与 `.obsidian-qa-profile/` 属于测试环境。插件代码和测试在 `core/obsidian-media-lab/plugin/`。本地 `architecture/projects/personal-media-system/` 可查系列架构和数据协议。实际本地路径变化时，以用户指定和已验证状态为准。
- 从 `验收/MediaBase 完整迁移验收/交付回执.md` 进入历史批次和回退说明。`Series 页首与来源复核` 有旧模板覆盖、笔记与归档验收、近次备份及正式写入回执。`Bangumi 补迁/核验回执.md` 记录已有刷新范围，并说明平台快照刷新和作品资料采纳的区别。历史报告是起点，取当前数量和归属要重新读正式库。

## 验证

1. 只读确认输入范围，检查身份冲突和活跃写入方。对已有计划和日志续跑，按 Work、Note、附件或链接判断影响。在隔离副本用真实样本先验证，再生成带前后哈希的计划。
2. 改插件时先跑受影响测试，在插件目录运行 `npm test`、`npm run build`。关注已有未提交改动，保留已发布构建。影响页面、Obsidian 链接或笔记创建时，补真实 Obsidian 副本验收。现有 `run-obsidian-qa.zsh` 配合 `obsidian-qa.mjs`，运行前确认隔离 profile、目标库路径和当次检查入口。等待所需元数据索引完毕，避免沿用上一次副本的缓存。网页或本地站点用 ChatGPT 内置浏览器，遵守本机禁止启动外部 Chrome 的规则。
3. 页面验收按问题挑实际样本。用《爱情公寓》检查成员均分、已完成无进度、短评、资料栏和全部作品入口，用《龙族》查作品笔记和来源笔记，用《起风了》查同名跨媒介及多目标随记。创作者与主题用可证多重归属样本。涉及滚动、浮层、关系图或画廊时执行 [界面验收](ui.md)。桌面窄栏检查只能报告桌面视口；手机或平板实机需另测。
4. 批量移动优先用 Obsidian 原生改名处理链接，然后核对有效目标、块 ID、标题锚点和相对附件。比较 UID、字段、正文和未涉及路径。来源导入重跑时检查 Note 不重复、同输入不重写、本地编辑不回滚。
5. 正式写入在用户任务已涵盖的范围内执行。先完成隔离复核、快照、回退准备，并检查目标无并发写入。沿用现有批次的前镜像保护和正式回执机制，实际应用后核验正式文件和必要页面。副本通过、本机部署、远端发布分别据实汇报。

6. 若请求包含远端合并，核对现有 PR 的分支、目标、隐私设置及当前提交的检查。优先更新已有 PR。只暂存代码、通用文档和可发布的示例；真实库、来源原件、截图、迁移日志和备份留在本机。合并后重新读取 PR 状态和远端目标提交，分别记录合并与正式库运行状态。
