# 归档和来源规则

## 系列、作品和笔记

- 已确认的物理基线是 `作品库/<系列>/<标题>（系列）.md`，同系列的 Work 按媒介直接放在系列目录下，真实 Note 放在同一系列的「笔记」。无需套一层通用「作品」目录或为单个 Work 建目录。沿用 `系统/`。父子系列用 `parent_series`，目录可以扁平。
- 同一作品按恰当粒度建档。剧集和动画按季或独立作品，漫画和轻小说通常按整部或整套，电影单列，版次另记。用整部平台条目、原名、年份、媒介、UID 或 ISBN 核实，保留明确的续作、番外、改编及版次边界。
- Work 的 `series` 可有多个关系。作品系列、创作者、主题集合是不同用途。创作者按实际署名关联，核对编剧、企划、原画、原作、插画、受访等不同角色。制作工作室、发行方、出版方、展览主题、原作作者与改编导演各有含义。书目按确切版次核对，图录编者与收录画稿绘制者分开。人工确认可用 `creator_credits` 的「角色|身份 ID」及来源链接，检查创作者目录和角色配置是否能解析。关联后在 Work 与创作者页确认可读标签。
- Note 的 `about` 提供可点双链，`about_refs` 对应 UID。确认目标后保留 Note UID、原文、标题锚点、块 ID、链接、相对附件与日期。单一系列内的记录进该系列「笔记」，同一 Work 的持续随记按需创建且复用。仍是独立作品的笔记放在该 Work 所在目录的「笔记」。真正跨档案的笔记只存一份，通过多目标链接聚合。无明确目标或历史冲突集中核对，保留原文。系列或作品的建立本身不生成空笔记。
- 「独立作品」清单先说明统计口径。仍在 `作品库/独立作品/` 的 Work 可能已经关联创作者或主题。需要判断可归属时逐条核对已有作品系列，再评估明确适合新建的系列。保留不确定项供复查。

## 资料与页面

- **作品资料**是可证的标题、主创、出版或发行资料和规模等。旧档有明确内容时优先结构化，按 Work 媒介、整部或版次分别落到已有规范字段。以 MediaArchive 实际使用的豆瓣、Bangumi 模板做字段清单。复杂证据、资源和原始快照放 `附件/数据/<Work UID>.json`。本阶段忽略豆瓣游戏。
- **平台数据**按来源身份保存。已确认 Bangumi 整部条目时优先重新读取当前平台资料，平台公开评分与本地个人评分分开。刷新先预览目标、字段和来源，保留本地手工字段与字段归属。相似标题、新版本和待收录旧条目独立判断。
- **用户数据**包括本人评分、状态、进度、短评、收藏与历史。旧档可补明确缺失值，不覆盖较新的本地编辑。不能从总集数反推已看集数，不能从公开评论填个人短评。来源中的含糊零计数保留为证据，有依据的实际零值保留在本地字段。
- Series 页首维持大封面、较窄简介和随阅读栏宽变化的布局。第二栏展示来源可靠的资料，例如原名、原作者、导演、编剧、制作方、出版方、发行年份、地区、语言及已知规模。共同字段与成员派生资料应如实标明，缺证据则留空。收藏状态分布、收录统计优先留在总览模块。展示缺字段时先检查源数据、结构化映射、预设与渲染。
- 笔记整理先抽样实际随记、长评、摘录和导入文档。统一标题层级和日期显示，保留时间原值和正文。微信读书去重在来源导入和重复同步中实现，过滤可确认已在 Work 表达的模板元数据。来源专有字段、用户附注和仅有的一份资料需保留，切勿用格式规则删掉未知区块。原文、来源段落身份、锚点和后续幂等性都要检查。
