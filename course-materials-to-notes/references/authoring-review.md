# 笔记编写与审校

## 一讲怎样形成可学习的内容

按先修概念 → 问题动机 → 定义与符号 → 核心结论 → 推导/例子 → 边界/误解 → 自测组织。模板可裁剪；不要求每一个小概念都有重复栏目。

掌握等级用于描述学习成果：

- **核心掌握**：能解释、写出关键关系及条件，完成一个代表性计算或反例。
- **熟悉**：能比较方法、判断适用场景、接回全课主线。
- **仅作了解**：知道背景与资料位置，暂不要求复现细节。

重点以课程明确要求和主线依赖为据；教师未说明时，标为笔记建议。每讲至少有若干真正考查理解的自测，避免只问缩写。双链只连有学习价值的关系，页面内锚点修改后检查入链。若同名文件会导致双链歧义，用路径区分。

原始材料不完备时，写清缺页、模糊公式或尚未发布的讲次。不要凭课程标题补写成已经读过的内容；必要的背景补充可给出可靠来源。

## 数学与算法核验

在结论附近写清条件，不把假设零散埋在别讲：

| 对象 | 优先核验 |
|---|---|
| 定义/矩阵 | 空间、形状、转置方向、可逆/正定/秩条件、广播与逐元素操作 |
| 定理/收敛率 | 算法类型、目标条件、误差量、步长和其依赖、索引/平均方式、随机性与下界 |
| 随机估计 | 采样分布、缩放、条件期望、独立性或条件无偏性、估计的目标是否被平滑 |
| 算法伪代码 | 更新顺序、梯度评估点、状态保留、精确子问题与一步近似是否混淆 |
| 成本估计 | 参数/梯度/状态/激活等对象、形状、字节数、单位、假设和实验条件 |

这些核验来自实际出现过的错误，适用时使用，不作为所有学科都必须出现的章节：

- 收敛率中的误差量不能互换：距离、距离平方、函数差、梯度范数平方有不同含义。任意小的固定步长往往使速率常数依赖 `1/步长`；特殊步长推得的界不自动适用于全部允许步长。
- 固定步长随机优化通常有噪声项。列明噪声矩、条件无偏/独立条件；有限迭代界与稳态不能混写。
- 随机方向采样与平滑分布可能不同。检查向量是否完整包含在期望中；前向差分与中心差分的公式、代价和偏差不同。
- 矩阵维度相容只说明能算，不证明算法正确。还需验证投影再回映、状态更新与最终参数的完整过程。
- 参数平均与梯度平均不同；更新的矩阵乘法方向依赖节点按行还是按列排列。共识、网络均值正确和每节点等价于同步算法是不同结论。
- 无偏压缩必须写明概率与缩放；二阶估计要检查随机向量的矩条件，而非凭方法名称断言无偏。

## 有意义的测试

先用手算/推导或独立形式得到参考值，再写实现；避免同一错误公式同时充当实现与标准答案。

按风险选择，不要求每讲凑固定测试数：

- 用有限差分检查梯度关系；选择使错误公式产生不同值的例子。
- 小维随机问题尽量枚举随机方向/选块，而非依赖不稳定蒙特卡洛；确需采样时固定种子，说明容差来源。
- 算法测试验证整个更新和必要的多轮行为；同时给一个破坏关键假设的反例。仅测平均矩阵、维度或文案无法检出更新顺序问题。
- 收敛界检查单步下降和求和关系，覆盖特殊步长、较小步长和边界；数值例子不能证明普遍定理。
- 内容回归可检查条件、符号、公式配套，但属于维护提示。文案变更引起失败时重新判断语义，不为了过测试退回错误表述。

测试依赖尽量轻量，只有确实需要才引入外部库。把结构验证与内容/数值验证分开，便于说明各自覆盖范围。新改动通过对应检查后，不无理由重复扩大测试。

## Markdown 与渲染

- 默认 `$...$` 与独立行的 `$$...$$`。行内公式尽量在同一行闭合；代码块、转义货币符号不当作公式。
- 复杂矩阵/分段式用多行；检查实际目标阅读器。不要将某次渲染器不支持的宏归结为所有版本永久禁止；存在兼容性问题时改用已验证的等价宏或写法。
- 中文标点与行内公式之间的空格可提高兼容性；脚本统计定界符只是启发式检查。
- Obsidian wiki 链接与标准 Markdown 相对链接各有用途；说明支持范围，避免使用本机绝对路径或 `file://` 作为共享仓库导航。

## 审查闭环

记录审查基准、逐项判断和最终改动位置；修订记录只需保留有助于理解改动的结果。既有用户授权的上传继续执行，无须为同一修订再次泛泛询问。

修订完成后核对整段论证和依赖它的例子/自测，避免局部替换公式却留下相反文字。对无法证实的意见明确不确定性；对课程原稿可能存在的问题保留出处和说明，不悄悄冒充教师原结论。上传后核实远端提交，再核实同一 SHA 的检查结果。
