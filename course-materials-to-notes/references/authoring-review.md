# 笔记编写与审校规则

## 学习笔记的组织

默认顺序为：先修概念 → 问题动机 → 定义与符号 → 核心结论 → 推导/例子 → 适用边界 → 自测。按学科特点裁剪栏目，不要每个小概念都机械重复全部栏目。

统一学习优先级：
- **🔴 必须掌握**：能够准确解释定义/核心关系及条件，并完成代表性推导、计算或论证。
- **🟠 重点理解**：能够解释机制、比较方法、判断适用场景并联系课程主线。
- **🟢 了解即可**：知道背景、用途和进一步查阅的资料，不要求掌握全部细节。

这些等级是笔记作者的学习建议；除非课程资料明确说明，不得把它们称为教师指定的考试重点。优先依据课程目标、课堂强调和知识依赖判断。

## 数学表达与推导

对重要数学对象和结论：
1. 定义符号、变量范围、向量/矩阵形状、单位及必要假设。
2. 说明目标问题与公式的来源；从已知条件到结论的关键推导步骤不能省略到无法复现。
3. 对算法明确输入、输出、更新顺序、函数评估点、状态保留和停止条件。
4. 解释公式中主要项的含义、适用范围及限制，并与容易混淆的概念区分。
5. 适合数值演示时给出小型可复算例子，展示输入、中间步骤和结果；数值例子用于理解，不替代一般性证明。

数学和算法核验按主题选择：
- 定义/矩阵：空间、形状、转置方向、秩、可逆性、正定性、广播与逐元素运算。
- 定理/收敛率：算法类型、目标条件、误差量、步长依赖、索引/平均方式、随机性和下界。
- 随机估计：采样分布、缩放、条件期望、独立性/条件无偏性，以及估计目标是否被平滑。
- 伪代码：更新顺序、梯度评估点、状态保留、精确子问题与一步近似的区别。
- 成本估计：统计对象、张量形状、字节数、单位、假设和实验条件。

不要把不同误差量（距离、距离平方、函数差、梯度范数平方）互换；不要仅凭维度相容就断言算法正确；不要把参数平均与梯度平均混为一谈。固定步长随机优化应检查噪声项和条件，有限迭代界不能直接写成稳态结论。以上是按需使用的检查项，不是所有学科的固定章节。

## 来源归属与不确定性

- 主要结论旁标明来源文件和实际页码/章节，明确是 PDF 页序还是印刷页码。
- 区分课件原文、由已知条件推导的结论、直观解释、外部补充和未证实推断。
- 多份来源综合时分别归属；原始材料有疑点时保留出处并说明，不悄悄把修正内容冒充原文。
- 不得仅凭目录、文件名或摘要推断整份资料的具体内容。缺页、模糊公式和未发布讲次应明确标注。

## Obsidian 与 Markdown 公式

- 行内公式默认使用 `$...$`；独立公式使用 `$$...$$`。代码块中的美元符号和转义货币符号不计为公式。
- 复杂矩阵、分段函数和多行推导采用多行结构；避免将过长表达式塞入行内公式。
- 检查上下标、括号、转置、粗体向量、矩阵维度、对齐环境和公式前后说明是否一致。
- Obsidian wiki 链接用于知识网络；标准 Markdown 相对链接用于 GitHub 等通用阅读器。GitHub 不原生解析 Obsidian 双链。
- 定界符脚本只能发现部分格式问题，不能证明公式语法正确或目标阅读器渲染正常。实际渲染需在目标阅读器中抽查。
- 不使用本机绝对路径或 `file://` 作为共享仓库导航。

## 自测与数值验证

- 自测应检验理解、条件、推导、计算或反例，而不只是缩写释义。
- 先通过独立推导或手算确定参考结果，再测试实现；避免同一错误公式同时作为实现和标准答案。
- 小规模随机问题优先枚举可能情况；确需采样时固定种子并说明容差。数值例子不能证明普遍定理。
- 测试应覆盖完整更新过程和必要的多轮行为；只检查维度或文案不足以检出算法错误。
- 结构检查、数值测试、内容审校和渲染检查应分别报告。不得将其中一类通过宣称为全面正确。

## 审校闭环

- 记录审查基准和逐项结论：已解决、确认并修正、部分成立、不采纳（说明理由）或待证实。
- 修改重要公式时同步核对邻近说明、假设、例子、自测和总览。
- 修订记录集中维护在 `REVISION_NOTES.md`，只保留有助于理解变更的结果。
- 对无法证实的意见明确不确定性；用户只要求审校时不重写无关部分。
