# 笔记编写与审校

## 学习组织原则

按先修概念 → 问题动机 → 定义与符号 → 核心结论 → 推导/例子 → 边界/误解 → 自测组织。模板可以裁剪，不要求每个概念重复所有栏目。

统一掌握等级：
- **🔴 必须掌握**：能准确陈述定义/结论及条件，完成关键推导或代表性计算，并识别常见反例。
- **🟠 重点理解**：能解释机制、比较方法、判断适用场景并联系课程主线。
- **🟢 了解即可**：知道背景、用途和进一步查阅位置，不要求复现全部细节。

重点应依据课程明确要求与知识依赖；教师未说明时，必须标为学习建议，不得断言是考试重点。每讲应有真正检验理解的自测。双链只连接有学习价值的关系；修改标题后检查入链，重名页面使用路径区分。

原始材料不完整时，记录缺页、模糊公式或未发布讲次。不得凭课程标题补写成已经读过的内容；背景补充应给出可靠来源。

## 数学与算法内容标准

在结论附近写清条件，不把假设零散埋在别讲。按实际主题核验：

| 对象 | 优先核验 |
|---|---|
| 定义/矩阵 | 空间、形状、转置方向、可逆/正定/秩条件、广播与逐元素操作 |
| 定理/收敛率 | 算法类型、目标条件、误差量、步长及其依赖、索引/平均方式、随机性与下界 |
| 随机估计 | 采样分布、缩放、条件期望、独立性或条件无偏性、估计目标是否被平滑 |
| 算法伪代码 | 更新顺序、梯度评估点、状态保留、精确子问题与一步近似是否混淆 |
| 成本估计 | 参数/梯度/状态/激活等对象、形状、字节数、单位、假设与实验条件 |

- 距离、距离平方、函数差和梯度范数平方不可互换。收敛率须写清误差量、常数和步长条件。
- 固定步长随机优化可能存在噪声项。列明矩条件、条件无偏/独立假设；区分有限迭代界与稳态行为。
- 随机方向采样与平滑分布可能不同。检查期望中的向量、缩放以及前向差分和中心差分的偏差、方差与计算代价。
- 矩阵维度相容不代表算法正确；验证投影/回映、状态更新及最终参数的完整过程。
- 参数平均与梯度平均不同；矩阵乘法方向依赖数据排列约定。区分共识、网络均值正确和每节点等价于同步算法。
- 无偏压缩必须写明概率与缩放；二阶估计需检查随机向量的矩条件，不能凭方法名称断言无偏。

以上学科专用检查只在主题相关时应用，不应强行出现在其他学科笔记中。

## 推导与数值例题

- 对核心结论说明前提、推理链与结果；不能只给公式和口头直觉。
- 对适合数值演示的算法，写明输入、符号/维度、初始状态、每次更新所用的量、中间值和最终结果。数字应能由展示的步骤复算。
- 对关键公式可用手算、独立推导、有限差分或小规模枚举做交叉检查。测试例不能替代普遍证明。
- 给出反例时明确指出它破坏了哪一项假设，以及因此不能推出什么。
- 将课件原结论、独立推导、外部资料补充和直观类比明确区分。若原稿可能有误，保留出处并说明疑点，不静默改写为教师原结论。

## 有意义的测试

先通过独立推导或手算得到参考值，避免同一错误公式同时充当实现和标准答案。按风险选择：
- 用有限差分检查梯度关系，并选取能区分候选公式的输入。
- 小维随机问题优先枚举方向/选块；确需采样时固定种子并说明容差。
- 算法测试覆盖完整更新与必要的多轮行为，也覆盖破坏关键假设的反例。
- 收敛界检查单步关系、求和步骤和边界情况；数值例子不能证明普遍定理。
- 内容回归测试可检查条件、符号与公式配套，但不能代替语义判断。

测试依赖尽量轻量。结构验证、数值验证与数学论证分别报告；文案检查失败时应判断语义，不为通过测试而恢复错误表述。

## Markdown、Obsidian 与渲染

- 默认行内公式使用 `$...$`，块级公式使用独立行的 `$$...$$`。行内公式尽量在同一行闭合；代码块、转义货币符号不当作公式。
- 复杂矩阵、分段式和多行推导采用清晰的多行格式。不要因某个渲染器不支持某宏就宣称所有版本均不支持；有兼容性问题时换用经过验证的等价写法。
- 中文标点与行内公式间适当留空格可改善部分阅读器兼容性。
- 定界符脚本检查只是启发式检查，不等于实际渲染通过。最终至少检查代表性的复杂公式、矩阵、表格与链接；无法实际打开目标阅读器时如实说明。
- Obsidian wiki 链接与标准 Markdown 相对链接用途不同。共享仓库不要使用本机绝对路径或 `file://` 导航。

## 审查闭环

记录审查基准、逐项判断与最终改动位置。修订完成后检查整段论证和依赖它的例子、自测、索引与链接，避免只替换公式却留下相反文字。对无法证实的意见明确标记不确定性。上传后核实远端提交，再核实同一 SHA 的检查结果。
