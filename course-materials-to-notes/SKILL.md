# 课程资料整理、学习笔记与审校

目标是交付可持续维护的课程资料库：来源可追溯，笔记有先修主线，关键结论注明条件，修改可验证。默认使用用户语言，保留常用英文术语。

## 适用范围与工作模式

根据用户实际目标选择一种主模式；不要把所有模式机械地叠加。

1. **课程学习笔记**：用户希望理解课程、建立知识体系或逐讲整理资料时使用。允许重组与适度提炼，但关键定义、结论、条件和推导不能因压缩而丢失。
2. **原文重建**：仅当用户明确要求尽可能完整地还原教材、讲义或数学 PDF 时进入。保留原章节顺序、定义、定理、证明、例题及关键措辞；不以摘要替代原文。将 OCR/图像识别不确定处标记出来并回看原页。
3. **审校与修订**：用户提供审查意见或要求检查现有笔记时使用。读取当前版本和审查基准，逐项核实、最小化修改并回归检查；不要重写未涉及的整门课程。
4. **不适用情形**：只问一个概念、公式或作业小题时，直接回答即可，不应自动启动完整的课程资料库流程。作业求解与报告交付优先使用 `homework-delivery`。

## 进入流程

- 新课程从来源盘点开始；已有课程先读取 README、来源清单、修订记录和 Git 状态，接续已有结构与命名。
- 用户只提供审查报告时，读取完整报告并对照当前本地/远端版本，不重新下载或重写整门课程。
- 只有用户要求上传、建仓库或同步时才执行发布操作；本 Skill 本身不构成发布授权。
- 不将某门课程的讲数、主题、年份、仓库、用户身份或旧提交写成通用常量。

## 1. 盘点与归档

1. 读取课程入口或本地原始目录，确认当前实际发布的讲次、材料、参考阅读、作业及课程年份。区分当年核心、跨年复用、补充参考和未确认范围。
2. 创建独立交付目录并尽量保留已有合理结构。通常包含 `README.md`、`source_manifest.tsv`、`checksums.sha256`、`resource_inventory.md`、`REVISION_NOTES.md`、`materials/`、`notes/` 和必要的 `tools/`。
3. 清单使用 UTF-8 TSV，至少包含 `lecture, role, original_path, source_url, target_path, status`。状态只能是 `downloaded` 或 `unavailable`；不可获取的资源须记录原因，不以错误页冒充成功。
4. URL 规范化去重，并用内容哈希识别异名同文档。跨讲次引用可共用文件，但保留各自清单行。名称冲突不能覆盖不同内容。
5. 下载后核验文件格式与可解析性。HTTP 成功不代表拿到课件；登录页和 HTML 错误页不能作为 PDF。首次确认内容后生成 SHA-256；后续先比对差异，不可通过重算哈希掩盖意外替换。
6. 保留来源与作者归属，记录获取日期；不缓存认证信息。说明缺件、格式、唯一文件数及可核实页数。

## 2. 构建学习笔记

阅读 [编写与审校规则](references/authoring-review.md)，参考 [讲次模板](assets/lecture-note-template.md)，并按学科特点裁剪。

- 先建立全课知识路线、讲次索引、先修关系和课程范围，再逐讲读取材料正文。目录与文件名只能辅助定位，不能替代对正文的阅读。
- PDF/PPTX 等按可用工具提取；涉及公式、图示、排版或 OCR 歧义时查看原页。无法核实的部分明确标记，不猜测补全。
- 统一掌握等级：
  - **🔴 必须掌握**：能够准确陈述定义/结论及条件，完成关键推导或代表性计算，并能识别常见反例。
  - **🟠 重点理解**：能够解释机制、比较方法、判断适用场景，并联系课程主线。
  - **🟢 了解即可**：理解背景、用途和进一步查阅的位置，不要求复现全部细节。
  等级反映学习建议，不冒充教师明确要求或考试范围；若课程标准另有要求，以课程标准为准。
- 数学或算法内容应在适用时说明对象、符号、维度、假设、推导步骤、结论和适用边界。适合数值演示的算法，应给出输入、关键中间量、更新顺序和输出，不能只给结论。
- 区分课件原有结论、从前提推导的结果、外部资料补充和直观解释。重要结论标注原文件与核实后的 PDF 页序或印刷页码。
- 用 `[[Lecture-XX_Topic#标题|说明]]` 连接必要先修与后续概念，并提供 GitHub 可点击的标准 Markdown 索引。GitHub 原生不解析 Obsidian 双链，不能宣称两处均可点击。
- 不为每个小概念重复所有模板栏目；结构服务于理解，不服务于填表。

## 3. 验证与审校

- 先做结构检查：文件、来源清单、状态、哈希、讲次覆盖、本地链接与公式定界符。运行 `python3 tools/verify_pack.py .`（或从 skill 目录运行单元测试）；按课程盘点结果提供 `--expected-notes` 与 `--expected-lectures`，而非硬编码讲数。
- 再做内容检查：定义、定理条件、维度、误差量、步长、随机性、算法更新顺序及来源对应关系。参考文档中的学科专用清单只在相关主题出现时使用。
- 最后检查目标阅读器中的复杂公式、矩阵、分段式、表格和链接。定界符检查不等于渲染通过；未能实际渲染时须说明。
- 将外部审查作为待核实线索。逐项记录为已解决、确认并修正、部分成立、不采纳并说明理由、待证实。数学问题回到原始资料或独立推导；外部查证优先原论文和官方文档。
- 改公式时同步检查假设、邻近解释、例子、自测、索引和相关链接。修订记录集中维护在 `REVISION_NOTES.md`，避免重复散落在多个文件。
- 测试通过不等于数学正确；文案检查不能代替推导。用户未要求持续巡查时，一轮问题关闭并交付即可。

## 4. GitHub 同步（用户要求时）

阅读 [GitHub 交付](references/github-delivery.md)。检查分支、远端状态和暂存差异；只上传目标资料库，排除个人作业、缓存、编辑器状态、认证信息与本机绝对路径。推送后核对远端提交 SHA；若存在 CI，检查对应同一 SHA 的结果。

## 交付说明

说明资料/笔记位置、实际覆盖与缺件、重要修正、验证范围，以及（若执行上传）仓库、提交和 CI 链接。明确区分本地完成、已推送、远端检查通过。遇到工具或权限阻碍时，完成不受影响的工作并报告剩余事项，不把未上传或未验证说成完成。
