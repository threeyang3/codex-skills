# 课程资料与学习笔记

目标是建立可持续维护、来源可追溯、适合主动学习的课程资料库。默认使用用户语言，保留重要术语的常见英文名称。先判断任务模式，再只执行该模式需要的步骤。

## 触发边界与模式选择

适用于：整门课程或多讲资料归档、分讲学习笔记生成、既有课程笔记审校修订，以及用户明确要求的原文重建。

不适用于：普通概念问答（直接回答即可）、独立作业求解或实验报告（使用 homework-delivery）、单个文件的纯格式转换（除非用户明确要求按原文重建）。

从以下模式中选择一个主模式；混合任务可按顺序组合：

1. **学习笔记模式**：目标是理解、复习和建立知识体系。允许在不歪曲来源的前提下重组材料、补充必要推导和例题。
2. **原文重建模式**：目标是尽可能忠实地还原教材/讲义内容、章节结构和数学表达。不得以摘要替代原文；对无法辨识之处标记不确定性，不凭空补全。
3. **审校修订模式**：目标是核查或修复已有内容。先读取现有版本、来源和审查意见，逐项判断并修改，不重新生成未受影响的整门课程。
4. **资料归档模式**：目标是清点、下载、分类和建立来源清单。只有用户要求笔记时才进入笔记生成阶段。

用户明确指定的目标优先于默认模式。若目标不清楚且不同模式会导致实质不同的产物，只询问一个必要问题。

## 1. 盘点与归档

- 新课程从来源盘点开始；已有课程先读 README、来源清单、修订记录和 Git 状态，沿用合理结构。
- 确认当前课程年份、实际发布讲次、材料区、参考阅读、作业及范围。区分当年核心、跨年复用、补充参考和未确认范围；不得将网页注释中的旧课程链接自动混入。
- 不把讲数、资源数、主题、年份、仓库、用户身份或旧提交写成通用常量；从本次来源确定。
- 通常使用 `course-learning-pack/`，包含 README、`source_manifest.tsv`、`checksums.sha256`、资源索引、修订记录、materials、notes 和 tools。保留已有项目的合理结构，不为套模板而破坏项目。
- 清单为 UTF-8 TSV，至少包含 `lecture, role, original_path, source_url, target_path, status`；状态只能为 `downloaded` 或 `unavailable`。本地来源可用 `local:` 标记，不记录个人绝对路径。无法获取的原因写入额外说明列或资源索引。
- 规范化 URL 去重，并用内容哈希识别异名同文档；跨讲次引用保留各自清单行。文件名冲突不得覆盖不同内容。
- 下载后核对文件格式与可解析性。HTTP 成功不代表下载到课件；登录页和 HTML 错误页不能冒充 PDF。首次确认内容后生成 SHA-256；后续先比对差异，不能通过重算哈希掩盖意外替换。
- 保留来源、作者归属和获取日期；不缓存认证信息。说明缺件与无法核实的页数。

## 2. 学习笔记模式

阅读 [笔记编写与审校规则](references/authoring-review.md)，参考 [讲次模板](assets/lecture-note-template.md)，按学科特点裁剪栏目。

- 先建立全课知识路线、讲次索引、先修关系和课程范围，再逐讲阅读正文。不能只根据目录或文件名总结材料。
- PDF/PPTX 按可用文档工具提取；涉及公式、图示、排版或 OCR 歧义时查看原页。未实际查看的内容不得声称已核实。
- 学习优先级统一使用 **🔴 必须掌握**、**🟠 重点理解**、**🟢 了解即可**。这是笔记的学习建议，不是教师公布的考试重点，除非来源明确如此。
- 重要结论应说明定义/前提、推导或证据、适用范围和限制。数学/算法主题要声明符号、维度、运算顺序与必要假设；适合数值演示的算法应给出关键中间步骤，不能只列最终式。
- 明确区分课件原结论、由前提推导的结论、辅助直觉解释和外部补充。对课件可能存在的问题保留出处并标明，不悄悄替换成貌似原文的修正版本。
- 对主要主题记录原文件和实际页码，说明页码指 PDF 页序还是印刷页码；综合多份来源时分别标注。
- Obsidian 使用有意义的 `[[笔记#标题|说明]]` 双链，并提供标准 Markdown 讲次导航。GitHub 不原生解析 Obsidian 双链，不得声称两处都可点击。
- 默认行内公式使用 `$...$`，独立公式使用 `$$...$$`。复杂矩阵、分段式与多行推导应使用清晰的多行结构；检查目标阅读器的实际渲染，而非仅统计定界符。

## 3. 原文重建模式

- 尽量保留原章节顺序、定义、定理、证明、例题、注释和数学用语；不得为了“更易读”擅自压缩或改写成学习摘要。
- 对数学表达优先依据页面图像识别，OCR 仅作为辅助。核对上下标、希腊字母、矩阵形状、分段条件、编号和引用关系。
- 无法辨认的内容明确标注页码和不确定片段；禁止静默猜测。必要时分批处理并对照相邻页，保持章节连续性。
- 交付前抽查复杂公式、分页和章节结构；明确说明未能核验的页面或公式。

## 4. 审校修订模式

- 记录审查所依据的提交/文件版本。将每条意见判定为：已解决、确认并修正、部分成立、不采纳（说明理由）或待证实。
- 数学问题回到原始资料或独立推导；外部查证优先原论文和官方文档。不得仅因审查者语气肯定就采纳。
- 修改公式时同步检查相邻解释、假设、例题、自测和总览。修订记录集中放在 `REVISION_NOTES.md`，避免多个文件重复维护同一轮历史。
- 用户只提供审查报告时，不重新下载或重写整门课程；只处理相关问题和必要依赖。
- 测试通过不等于数学正确；文案检查不能证明内容正确。用户未要求持续巡查时，关闭本轮问题并交付，不自行创建循环任务。

## 5. 验证与审查

先做结构验证，再做内容验证，最后检查实际阅读体验。

- 将 [verify_pack.py](scripts/verify_pack.py) 复制到交付目录的 `tools/`，从交付根目录运行 `python3 tools/verify_pack.py .`。脚本检查清单字段/状态、文件存在性、SHA-256、笔记讲次覆盖、部分本地链接及公式定界符；它不检查外链连通性、不解析所有 Markdown 方言，也不能证明数学正确。
- 清单中的 `lecture` 标识必须能与笔记文件名对应，例如 `Lecture-01` 对应 `Lecture-01_Topic.md`。按课程盘点提供 `--expected-lectures Lecture-01,Lecture-02` 和可选的 `--expected-notes N`，显式检查清单与笔记覆盖。未提供课程范围时，至少检查已下载资料对应的讲次是否有笔记；仅含 `unavailable` 记录的讲次可暂缺笔记。`unavailable` 行的 `target_path` 必须为空，缺件原因另行记录，不得伪造文件或调整清单掩盖缺漏。
- 内容检查定义、定理条件、维度、误差量、步长、随机性、算法更新顺序和来源对应关系。只对实际出现的高风险结论增加数值测试；参考 authoring-review 中适用的检查项。
- 在目标阅读器中抽查代表性的复杂公式、矩阵、表格和链接。无法实际查看的部分如实说明；不能将定界符检查称为渲染通过。
- 在 skill 根目录运行 `python3 -m unittest discover -s scripts -p 'test_*.py'`，检查清单字段、缺件、哈希、链接、公式定界符和课程讲次覆盖。

## 6. GitHub 同步（仅在用户要求时）

阅读 [GitHub 交付](references/github-delivery.md)，复用已有仓库和授权。只上传课程交付目录，排除个人作业、缓存、编辑器配置与认证信息。核验本次提交 SHA 与远端检查结果。

## 交付说明

说明资料和笔记位置、实际覆盖与缺件、重要修正、检查范围，以及上传时的仓库/提交/CI 链接。区分本地完成、已推送、远端检查通过。工具或权限受阻时完成不受影响的工作，并明确剩余事项。
