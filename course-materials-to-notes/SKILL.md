# 课程资料整理、笔记与审校

交付可持续学习和维护的课程资料库：原文件可追溯，笔记有先修主线，重点结论带条件，修订能核验，远端状态可确认。默认用用户语言写笔记，保留术语的常用英文名称。

## 进入流程

- 新课程：从来源盘点开始；已有课程：先读 README、来源清单、修订记录和 Git 状态，接续已有目录及命名。
- 用户仅提供审查报告：读取完整报告及其中的请求，以当前本地/远端版本核对问题，执行“审查与修订”，不重新下载或重写整门课程。
- 上传是条件环节：只有用户已要求上传/建仓库/同步时执行；此前授权在同一任务中继续有效。本 skill 本身不构成发布授权。
- 不把某门课程的讲数、资源数、主题、年份、仓库、用户身份或旧提交写成通用常量。先从本次来源得出这些值。

## 1. 盘点与归档

1. 读取课程入口或本地原始目录，确认当前实际发布的讲次、材料区、参考阅读、作业及课程年份。区分当年核心、跨年复用、补充参考和未确认范围；不将网页注释内的旧课程链接自动混入。
2. 创建独立交付目录，保留已有合理结构。通常采用：

   ```text
   course-learning-pack/
   ├── README.md
   ├── source_manifest.tsv
   ├── checksums.sha256
   ├── resource_inventory.md
   ├── REVISION_NOTES.md
   ├── materials/Lecture-01_Topic/01_topic_slides.pdf
   ├── notes/README.md
   ├── notes/COURSE_SCOPE.md
   ├── notes/Lecture-01_Topic.md
   └── tools/
   ```

   仅按需要增加 `REFERENCES.md`、复用下载脚本、CI 等；不为了符合模板改坏现有项目。
3. 规范文件名：`Lecture-序号_简短主题/讲内序号_主题_角色.扩展名`。原名、原 URL 和讲次对应关系保留在清单中。来源包含多种格式时保留原格式；不把 PPTX 等伪装为 PDF。
4. 清单使用 UTF-8 TSV，字段为 `lecture, role, original_path, source_url, target_path, status`，以制表符分隔。`target_path` 为交付根目录的相对路径；`status` 为 `downloaded` 或 `unavailable`。本地来源可用 `local:` 标记，避免写入个人绝对路径。无法获取时在 `note` 扩展列或资源索引记录原因，不用空白/错误页冒充成功。
5. 规范化 URL 去重，并用内容哈希识别异名同文档；跨讲次引用保留各自清单行，可共用一个文件。名称冲突不能覆盖不同内容。
6. 下载使用可重试、可恢复的方式。逐文件核对格式/可解析性：HTTP 成功不代表下载到课件，登录页与 HTML 错误页不能作为 PDF。首次确认内容后生成 SHA-256 清单；后续先比对差异，不能用重算哈希掩盖意外替换。
7. 保留来源与作者归属。缓存原网页或记录获取日期；不缓存认证信息。统计唯一文件数、格式和可核实的页数，并说明缺件。

## 2. 阅读与构建笔记

阅读 [编写与审校规则](references/authoring-review.md)。参考 [讲次模板](assets/lecture-note-template.md)，按学科特点裁剪。

- 先建立全课知识路线、讲次索引、先修关系和课程范围，再逐讲读取正文。目录与文件名只能辅助定位，不能作为总结整份材料的依据。
- PDF/PPTX 等按环境中可用的文档工具提取；涉及排版、图示、公式或 OCR 歧义时查看原页。可用相应 PDF/演示文稿 skill；缺少该 skill 时使用实际可用的解析和渲染工具，说明未核实之处。
- 每讲使用稳定文件名和标题，内容循序渐进；标记 **核心掌握**、**熟悉**、**仅作了解**，说明各等级需要达到的能力。难度等级参考课程要求，不擅自断言考试重点。
- 用 `[[Lecture-XX_Topic#标题|说明]]` 连接必要的先修与后续概念，同时提供可在 GitHub 点击的标准 Markdown 讲次索引。原生 GitHub 不解析 Obsidian 双链，不能宣称双链在两处都可点击。
- 对主要主题给出原文件及实际页码，明确 PDF 页序还是印刷页码；综合不同来源时分别归属。自行补充的推导、例子与资料原结论可区分。

## 3. 验证与审查修订

- 先做结构验证：实际文件、来源清单、哈希、链接、讲次覆盖与公式定界符。可把 [verify_pack.py](scripts/verify_pack.py) 复制到交付目录的 `tools/`，以 `python3 tools/verify_pack.py .` 执行，支持 Python 3.9+。可加 `--expected-notes N` 核对从本课程盘点得到的讲数；缺件通过 `status` 明确保留。脚本不检查外链连通性和全部 Markdown 语法，也不证明内容正确；课程范围与讲次是否完整仍需对照来源。
- 再做内容验证：定义、定理条件、维度、误差量、步长、随机性、算法更新顺序和来源对应关系。应用 [编写与审校规则](references/authoring-review.md) 的高风险核验方法；仅为实际高风险结论增加数值测试。
- 最后检查目标阅读器中代表性复杂公式、矩阵、表格和链接。无法实际查看的部分如实说明，不把定界符检查称为渲染通过。
- 外部审查是待核实的线索。记录报告基准提交，与最新版本比对；对每项判断为已解决/确认并修正/部分成立/不采纳并给理由/待证实。数学问题回到原始资料或直接推导；查证外部资料时优先原论文和官方文档。
- 修改公式时同步邻近说明、假设、例子、自测、测试和总览。审校轮次不要散落在 README 等多处维护；用“持续审校”并链接 `REVISION_NOTES.md`。旧修订记录若包含错误结论，注明后续纠正位置，避免继续误导。
- 测试通过仍不等于数学正确；文案字符串检查仅防止特定退化。用户没有要求无限巡查时，一轮问题关闭并交付即可，不自行设置循环任务。

## 4. GitHub 同步（用户要求时）

阅读 [GitHub 交付](references/github-delivery.md)，按既有授权创建或复用仓库、提交、推送，核验本次提交与 CI。只上传课程交付目录，排除同级个人作业、缓存、编辑器配置与认证信息。

## 交付说明

给出资料/笔记位置、实际覆盖与缺件、重要修正、检查范围，以及已执行上传时的仓库、提交和本次 CI 链接。区分本地完成、已推送、远端检查通过三个状态。遇到工具/权限阻碍时完成不受影响的本地工作，明确剩余项，不把未上传或未验证说成完成。

维护验证脚本时，在 skill 根目录运行 `python3 -m unittest discover -s scripts -p 'test_*.py'`，检查篡改、缺件、链接、公式定界符和可变课程规模等行为。
