# 作业求解、实验报告与交付

目标是按题目要求完成可核查的解答或实验，并交付内容一致、文件齐全的结果。先判断任务模式，再按需执行流程；简单任务不必为了流程而额外生成大量过程文档。

## 触发边界与模式

适用于：理论作业、编程作业、数值/仿真实验、实验报告，以及用户明确要求的提交包整理。

不适用于：普通概念问答（直接解释）、整门课程资料库建设或多讲学习笔记（使用 course-materials-to-notes）、单纯代码调试且与作业交付无关的任务（优先直接处理调试问题）。

选择一个主模式；混合任务可组合执行：
- **理论作业**：题目 → 分析思路与必要概念 → 正式解答。
- **编程作业**：题目要求 → 算法设计 → 实现 → 运行验证 → 结果说明。
- **实验报告**：目标与方法 → 实现/实验设置 → 实际结果 → 分析与结论。
- **纯交付整理**：尽量不改动已完成的正文，重点核对格式、文件、依赖和提交要求。

## 1. 解析题目并建立验收清单

- 阅读题目全文、评分标准、提交说明、起始代码、数据和目录结构。不要仅凭文件名或局部片段开始作答。
- 列出全部小题及其交付要求：需要回答的结论、证明/计算、代码接口、图表、数据文件、报告格式和命名规则。
- 对每项要求标记完成条件和验证方式。遇到相互矛盾或会改变解答的缺失信息时，先询问必要问题；其他情况下按合理假设继续并写明。
- 保留题目原文或准确的题意转述，使最终文档脱离原始 PDF 后仍可理解；用户明确要求只交答案时除外。

## 2. 求解与实现

### 理论作业
- 每题采用“题目—分析—正式解答”结构。
- **分析部分**可较详细，说明考察内容、解题思路和首次出现的重要概念；对专业术语给出必要定义。
- **正式解答部分**在步骤完整且推导正确的前提下尽量简洁，多用公式与符号，减少冗长叙述。不得为了简洁省略关键推理或必要条件。
- 检查符号、维度、假设、定理条件和边界情况；不确定的结论应继续核实或明确标注。

### 编程作业
- 先理解题目要求、输入输出、给定接口和依赖，再设计算法；除非必要，不擅自更改题目提供的文件名、函数签名和数据格式。
- 保持必要的源代码、数据和相对路径。区分运行依赖与临时文件，不因文件类型而误删必要数据。
- 有可用环境时实际运行程序，记录真实命令和结果；运行失败时分析原因，不将静态检查描述成运行通过。
- 根据任务选择测试：代表性输入、边界情况、形状/类型、可重复性及与独立参考结果的对照。测试规模和依赖应与任务相称。

### 实验报告
- 报告只描述实际执行的实验、实际获得的数据和真实观察。不得编造运行经历、数值、图表或实验结论。
- 说明关键实验设置、算法参数、随机种子（适用时）、环境与结果限制，以便复现。
- 图表应来自真实数据；核对标题、坐标轴、单位、图例和正文解释的一致性。
- 将实验观察与理论解释区分开。结果不符合预期时分析原因，不隐藏失败结果。

### 纯交付整理
- 尽量保留原始目录结构和文件名。优先只处理用户要求的交付问题，不重写已经完成且未发现问题的内容。
- 提交包仅包含报告、相关源代码、运行所需数据和题目要求的结果。依赖说明按需保留；缓存、虚拟环境、编辑器状态、临时文件默认不打包。
- 仅在题目或用户要求压缩包、或提交场景确实需要时才创建 ZIP。

## 3. 报告与 PDF

- Markdown 可作为可编辑的正文来源。用户要求 PDF 时，从核验后的正文生成，避免另写不一致的版本；根据公式、表格和代码复杂度选择可用且可靠的排版路径。
- 公式、表格、代码和图表按任务需要保留，不堆砌形式化检查清单。
- PDF 生成后检查实际页面：公式切断、表格溢出、代码换行、字体、图像清晰度、页码和分页。仅生成文件不等于排版通过。
- 采用自然、朴素的课程报告语气，直接说明方法、实现、结果和必要分析；少用套话、重复总结、自我评价和流程播报。

## 4. 最终验收

逐项对照阶段 1 的验收清单：
- 所有题目/子题均有对应内容，题目要求的证明、计算、代码和结果齐全。
- 公式、变量、代码接口、数值、图表和正文相互一致。
- 可运行的代码已实际运行；未运行或未通过的部分明确说明。
- 所有必要数据、依赖说明和相对路径完整，提交目录无无关缓存或敏感凭证。
- PDF 已检查实际排版；如要求 ZIP，解压后检查目录和必要文件。
- 用户修改内容后，同步更新相关报告、代码、图表和打包文件，避免旧版本混入最终交付。

## 5. 个人偏好与信息保护

- 采用自然、朴素、直接的表达，不夸大结果，不虚构实验经历。
- 需要署名时使用用户当前明确提供的姓名/学号或现有作业配置；新指示优先。若信息缺失且署名确实必需，再询问，不猜测。
- 不将认证信息、无关个人文件或不必要的个人信息纳入提交包。
- 交付时简要说明产物位置、完成的验证、未完成/未运行事项及其原因。区分“已生成”“已运行验证”和“已通过验收”。
