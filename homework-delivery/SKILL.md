# 作业报告与交付

- 先阅读题目，记录原始目录结构、提交要求和程序所需文件。提交包尽量沿用原始文件名和层级，例如 `data/`、`main/`、`main/tools/`、`plots/`；不要为方便整理而改成另一套结构。
- 提交内容保持精简：报告、相关源代码、运行必需的数据和题目要求的结果图。数据是运行依赖，不能当作杂项删掉。依赖说明按需保留；测试、缓存、虚拟环境、临时文件、构建脚本和过程记录默认不打包，除非题目或用户要求。
- 报告先写成 Markdown，作为可修改的正文来源。用户要求生成 PDF 时，从核验后的 Markdown 转换，保持两者内容一致；不要另写一份不同的 PDF 正文。未要求 PDF 时先交付 Markdown。
- 采用自然、朴素的课程实验报告语气，直接说明方法、实现、结果和必要的分析。少用套话、重复总结、自我评价和流程播报；不夸大结果，也不编造实验经历。公式与表格按实际需要保留，不堆砌检查清单。
