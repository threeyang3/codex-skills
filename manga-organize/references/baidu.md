# 百度网盘交付

1. **定目录。** 优先沿用用户指定目录或同一版本的现有归档路径。用户的《作品》目录可能收录多版，先核对当前版别和同级命名，再复用或建立版别子目录。替换前记录原件与原侧车的精确名称、大小、文件 ID 和目标目录状态。新版与旧版不一一对应时先明确替换范围。
2. **暂存。** 仅上传已验收的成品和对应侧车。按工具实际能力操作。百度 MCP 的上传命令草稿不是传输结果，且适用路径有限。普通目录可用百度网盘桌面客户端通过 CUA 批量上传到本次专用暂存目录。大套可分组，在本地回读通过后开始上传，等每组到齐才做正式迁移。
3. **对账。** 本地留清单，列卷号、配对文件、大小和 SHA-256。上传结束后读网盘目录，逐项核对名称、精确大小和预期数量，并记录网盘 ID。远端有经验证可比对的校验值时再比较内容校验值。传输队列或百分比只能用于看进度。
4. **迁入。** 新归档把验收后的文件迁入正式位置。替换既有文件时，将精确匹配的旧文件移入本次专用「覆盖前备份」，核对备份内容后才移动成品。使用不覆盖同名项的操作，保留正式目录和其他版本。移动部分成功或响应不确定时先读回正式、暂存和备份，按已记录的 ID 和路径恢复后续步骤。
5. **最终验收。** 读回正式目录，核对本次全部成品和侧车的名称、大小、网盘 ID，并确认暂存已空。需要更新用户的进度表或未处理清单时，按实际版本和完成范围登记成品目录、格式、卷数、章节数、验收结果与必要备注。已经清理的备份只记作清理状态，成品记录不要再指向它。
6. **清理。** 正式验收通过且进度记录已写好后，按用户本次整理习惯，把已空的暂存目录及本次覆盖前备份移入网盘回收站，并核对目标消失、成品仍在。历史备份另行指定才处理。只清理确认属于本次且已交付的本地工作副本与临时提取文件；用户提供的本地唯一原件只有在其处置已授权、并确认有对应已验收的网盘文件时才清理。发生缺卷、替换失败、或原件包含成品之外的内容时，保留相应副本并记录原因。清理以可恢复操作为优先。
